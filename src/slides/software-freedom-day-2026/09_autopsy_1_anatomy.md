# Anatomy of a Successful PEP

## Key Insight

The **Motivation** section tells you if the author understands the real problem.

The **Backwards Compatibility** section tells you if the PEP will survive.

Everything else is supporting evidence.

## Live Paraphrase: PEP 484 Motivation

- "Annotations existed since 2006 but had **no meaning**"
- "Tools like mypy existed but had **no standard** to target"
- "Large codebases needed this for **refactoring**"
<!-- note:
- This is what a real problem statement looks like — it doesn't say "it would be nice," it says "we are already doing this and it hurts"
